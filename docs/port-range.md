# 自建服务端口区间的选择

本机的自建服务越来越多，每个服务都要一个监听端口。为了避免和常用软件的默认端口冲突，提前选定一个专用区间，新服务都从这个区间里分配。

## 结论

使用 **29000–29999**，从 **29100** 开始顺序分配，跳过 **29418**。

## 排除的范围

| 范围        | 排除原因                                                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------------------------------------ |
| 0–1023      | 特权端口，普通用户进程默认无法绑定                                                                                       |
| 32768–60999 | Linux 默认的临时端口范围（`net.ipv4.ip_local_port_range`）。出站连接会随机占用其中的端口，监听在这里的服务偶尔会绑定失败 |
| 30000–32767 | Kubernetes NodePort 的默认范围                                                                                           |

所以只在 1024–29999 之间挑选。

## 分析方法

以 1000 个端口为一段，用三份数据统计每段的占用密度：

- **Wikipedia 收录数**：[List of TCP and UDP port numbers](https://en.wikipedia.org/wiki/List_of_TCP_and_UDP_port_numbers) 中起始端口落在该段的条目数。跨度超过 200 个端口的大范围条目不计。这份列表收录了大量非官方但常见的默认端口。
- **IANA 已分配数**：[IANA 端口注册表](https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.csv) 中，该段内有服务名的 TCP 端口个数。
- **nmap 开放频率**：nmap 7.99 附带的 `nmap-services` 里，该段所有 TCP 端口的开放频率之和，单位为 10⁻⁴。这个频率来自对公网主机的扫描，反映的是端口实际被使用的程度。

三项都是越小越好。

## 候选区段对比

除了上面三份数据，还要看现代自建软件的默认端口，这类软件在 Wikipedia 和 IANA 里收录得不全。

| 区段        | 已知的常用服务                                                   |
| ----------- | ---------------------------------------------------------------- |
| 29000–29999 | Gerrit SSH 29418、RethinkDB 集群 29015、Siemens 许可证服务 29000 |
| 26000–26999 | Redis Sentinel 26379                                             |
| 24000–24999 | Barrier / Deskflow 24800、GlusterFS 24007–24008                  |
| 23000–23999 | 基本只有老游戏                                                   |
| 22000–22999 | Syncthing 22000                                                  |
| 21000–21999 | RustDesk 21115–21119、Syncthing 本地发现 21027                   |

29000–29999 里只有 Gerrit 的 29418 是开发工具常见的默认值。另外两个只有在用到 RethinkDB 集群或 Siemens 许可证服务时才会冲突。

## 29000–29999 内的已知占用

| 端口  | 来源                                                                                        | 说明                                |
| ----- | ------------------------------------------------------------------------------------------- | ----------------------------------- |
| 29000 | IANA                                                                                        | saltd-licensing，Siemens 许可证服务 |
| 29015 | nmap                                                                                        | RethinkDB 集群内部通信              |
| 29167 | IANA                                                                                        | otmp，ObTools Message Protocol      |
| 29418 | [Gerrit 文档](https://gerrit-review.googlesource.com/Documentation/config-gerrit.html#sshd) | Gerrit 内置 SSH 服务的默认端口      |
| 29999 | IANA                                                                                        | bingbang，风电场 IEC 61850 数据交换 |

从 29100 开始分配，前面的 29000 和 29015 自然避开，后面只需记得跳过 29418。

## 局限

- Wikipedia 和 IANA 对近几年流行的自建软件覆盖不全，所以补充了“候选区段对比”里的人工核对。
- nmap 频率统计的是公网上暴露的端口，只在本机或内网使用的服务反映得不够。
- 临时端口范围以 Linux 默认值为准。如果改过 `net.ipv4.ip_local_port_range`，要重新确认它和 29000–29999 不重叠。
